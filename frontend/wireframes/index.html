Desktop notes

  1. 1Email: single labelled field, full card width, autofocused on load, email keyboard on mobile.

  3. 3Show/hide: toggles the input type and keeps the caret position. Try it on this frame.

05

Review & sign-off

Phase 1 is not done until the team has reviewed these frames and approved them for Phase 2.

Phase 1 checklist Acceptance

  • Login screen covers email, password and Login on mobile + desktop.
  • Show/hide password is represented and demonstrable.
  • Error states: wrong credentials, empty fields, no internet.
  • Loading state after pressing Login is shown.
  • App layout has header, navigation with Log out, and a main content area.
  • Both breakpoints covered: 375px and 1440px.
  • Login → app screen flow documented.
  • Every element annotated with a note.
  • Team feedback applied and approval requested before Phase 2.

Out of scope: check-in/out screens, dashboard content, visual design and brand identity, password reset, sign-up. Phase 2 visuals are a Design deliverable.

Open questions for review

  • Ownership: S1-02 is tagged Design. Confirm Team 6 owns Phase 1 and that Phase 2 is not expected from us.
  • Mobile navigation: drawer (shown) or bottom bar? Drawer keeps the content area wider.
  • Log out placement: header on desktop, drawer on mobile. Is one tap still acceptable to the PO?
  • Copy ownership: final state wording belongs to S1-16; confirm examples here are placement-only.
  • Navigation items: does Staff need "My attendance", or only Clock in/out for Sprint 1?
  • Approval: who signs off Phase 1, and by when, so Phase 2 can start?
