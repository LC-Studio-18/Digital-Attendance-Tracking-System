# ST-04 - Design Loading, Success and Error States (Mobile and Desktop)

## Information
- Ticket ID: S1-16
- Assigned developer: Kirsten Layters
- Current QA status: Pass

## Objective
- Design and verify reusable loading, success, and error feedback states (`LoadingButton`, `AttendanceConfirmation`, `ErrorState`, `useAsyncAction`, and `mapApiError`) across mobile and desktop viewports for Product Owner approval.

## Acceptance Criteria
- [x] Loading button displays an active spinner, disables user clicks during execution, and prevents duplicate API calls.
- [x] Success state displays a clear confirmation banner with action details and recorded timestamp.
- [x] Error states accurately map network/API failures (offline, 401, 403, 409, 422, 500, 502) into user-friendly copy with a working retry control.
- [x] All feedback states render cleanly on both mobile (375px / 360px) and desktop viewports without horizontal overflow.
- [x] Build (`npm run build`) and linter (`npm run lint`) pass with zero errors.
